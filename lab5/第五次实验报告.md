> Copy-on-write（简称COW）的基本概念是指如果有多个使用者对一个资源A（比如内存块）进行读操作，则每个使用者只需获得一个指向同一个资源A的指针，就可以该资源了。若某使用者需要对这个资源A进行写操作，系统会对该资源进行拷贝操作，从而使得该“写操作”使用者获得一个该资源A的“私有”拷贝—资源B，可对资源B进行写操作。该“写操作”使用者对资源B的改变对于其他的使用者而言是不可见的，因为其他使用者看到的还是资源A。

##### 关于`page2kva`函数

**1. `KADDR(pa)`**

```c
#define KADDR(pa)                                                \
    ({                                                           \
        uintptr_t __m_pa = (pa);                                 \
        size_t __m_ppn = PPN(__m_pa);                            \
        if (__m_ppn >= npage) {                                  \
            panic("KADDR called with invalid pa %08lx", __m_pa); \
        }                                                        \
        (void *)(__m_pa + va_pa_offset);                         \
    })
```

**功能：** 将一个物理地址（`pa`）转换为对应的内核虚拟地址（`KVA`）。

**主要步骤：**

1. 提取物理页号（PPN）

   `PPN(__m_pa)` 是从物理地址中提取物理页号的操作，（通常为 `__m_pa >> PGSHIFT`，即去掉页内偏移部分）。

2. 合法性检查

   判断该物理页号是否超出系统的页总数 `npage`。如果超出，调用 `panic` 终止程序，报告错误。

3. 计算内核虚拟地址

   - 内核虚拟地址 = 物理地址 + 偏移量 `va_pa_offset`。
   - `va_pa_offset` 是内核虚拟地址和物理地址之间的固定映射偏移值。

------

**2. `page2pa(struct Page \*page)`**

```c
static inline uintptr_t
page2pa(struct Page *page) {
    return page2ppn(page) << PGSHIFT;
}
```

**功能：** 将 `struct Page` 对应的物理页结构转换为物理地址。

**主要步骤：**

1. 获取物理页号（PPN）

   调用 `page2ppn(page)` 获取 `page` 对应的物理页号。

2. 转换为物理地址

   将页号左移 `PGSHIFT`（页大小的位数），得到该页的起始物理地址。

------

**3. `page2kva(struct Page \*page)`**

```c
static inline void *
page2kva(struct Page *page) {
    return KADDR(page2pa(page));
}
```

**功能：** 将 `struct Page` 转换为对应的内核虚拟地址。

**主要步骤：**

1. 调用 `page2pa(page)`

   将 `Page` 结构体转换为物理地址。

2. 调用 `KADDR(pa)`

   使用 `KADDR` 宏将物理地址转换为内核虚拟地址。

3. 返回值

   返回的是内核虚拟地址，类型为 `void *`。

##### COW的实现思路（具体实现在challenge中实现）

 **(1) fork 时的行为**

1. **共享页表**：
   在 `fork` 系统调用时，操作系统不立即复制父线程的物理页数据，而是让子线程共享父线程的页表。此时：
   - 每个页表项的权限被标记为只读，即便原本是可读写的。
   - 父线程和子线程都指向同一块物理内存。
2. **栈和虚拟内存特殊处理**：
   子线程需要有自己的栈和虚拟内存管理结构，因此在创建时，系统会为它们分配独立的结构，但暂时不分配物理页。

 **(2) 子线程运行时的行为**

当子线程尝试**写入共享内存页**时，操作系统会检测到试图写入的页被标记为只读，从而引发一个页错误（Page Fault）异常。

**(3) 异常处理**

1. **捕获异常**：
   页错误的处理机制会识别出这是一次由写时复制引起的异常，而不是非法访问。
2. **分配新内存**：
   操作系统分配一块新的物理页。
3. **复制数据**：
   将父线程中原物理页的数据复制到新分配的物理页。
4. **更新页表**：
   更新子线程的页表，让它指向新分配的物理页，并将权限改回可读写。
5. **恢复执行**：
   异常处理完成后，子线程可以继续执行，访问的页面此时已是它自己的副本。

该函数通过内联汇编实现系统调用
```c
asm volatile (
    "ld a0, %1\n"
    "ld a1, %2\n"
    "ld a2, %3\n"
    "ld a3, %4\n"
    "ld a4, %5\n"
    "ld a5, %6\n"
    "ecall\n"
    "sd a0, %0"
    : "=m" (ret)
    : "m"(num), "m"(a[0]), "m"(a[1]), "m"(a[2]), "m"(a[3]), "m"(a[4])

```
这段内联汇编代码是实现系统调用的关键，它将系统调用号和参数加载到 a0 到 a5 寄存器中，并执行 ecall 指令，通过ecall指令会产生一个中断，进而从用户态转到内核态中关于中断异常处理的部分，之后trap.c中的exception_handler()函数对相应的系统调用进行转发（该过程通过中断帧里 scause寄存器的数值，判断出当前是来自USER_ECALL的异常，进而调用内核态的syscall()函数进行系统调用），接下来syscall 函数会提取系统调用的参数（从 a1 到 a5 寄存器），转发给系统调用编号对应的函数进行处理,具体的对应关系如下所示

而这些系统调用的函数封装了在kern/process/proc.c中对应系统调用函数的具体实现，比如sys_fork()函数就会调用do_fork()函数，而do_fork函数就是系统调用的具体实现，类似的还有do_execve()、do_wait()、do_exit()等都是系统调用的具体实现
在执行完系统调用后在trap返回的时候调用sret指令，这时只要sstatus寄存器的SPP二进制位为0，就会切换回用户态继续执行（load_icode()函数在构造新进程的时候，会把SSTATUS_SPP设置为0）

2. 内核态

内核态实现kernel_execve()函数进行系统调用不能直接调用do_execve()函数。do_execve() load_icode()里面只是构建了用户程序运行的上下文，但是并没有完成切换。上下文切换实际上要借助中断处理的返回来完成。但是在内核态没有办法使用ecall指令来创造中断，所以只用ebreak指令来产生断电中断并通过设置a7寄存器的值为10说明这不是一个普通的断点中断，而是要转发到syscall()，这样就完成了内核态的

根据上面的分析，在正常在用户态执行用户程序的时候碰到系统调用的函数时，在执行ecall指令进入到中断处理阶段之前是在用户态完成的，而开始执行trap.c中的exception_handler()函数进行系统调用的转发，再到syscall（）函数把系统调用进一步转发给proc.c的do_exit(), do_fork()等函数，再到do_exit()等函数执行等操作是在内核态完成的。

1. do_fork()函数

```c
int do_fork(uint32_t clone_flags, uintptr_t stack, struct trapframe *tf) {
    // 初始化返回值为 -E_NO_FREE_PROC，表示没有可用的进程
    int ret = -E_NO_FREE_PROC;
    struct proc_struct *proc;
    
    // 检查系统内进程数量是否已达上限
    if (nr_process >= MAX_PROCESS) {
        goto fork_out;
    }
    ret = -E_NO_MEM; // 初始化返回值为 -E_NO_MEM，表示内存不足

    // 分配一个新的进程结构体
    proc = alloc_proc();
    
    // 如果分配失败，跳转到fork_out处理错误
    if (proc == NULL) {
        goto fork_out;
    }

    // 设置新进程的父进程为当前进程
    proc->parent = current;

    // 为新进程设置内核栈
    if (setup_kstack(proc) != 0) {
        goto bad_fork_cleanup_kstack;
    }

    // 复制内存管理结构体（如果需要）
    if (copy_mm(clone_flags, proc) != 0) {
        goto bad_fork_cleanup_proc;
    }

    // 复制线程特定数据（如寄存器状态）
    copy_thread(proc, stack, tf);

    // 禁用中断，保护临界区
    bool intr_flag;
    local_intr_save(intr_flag);
    
    // 为新进程分配一个唯一的PID
    proc->pid = get_pid();
    // 将新进程加入到进程哈希表中
    hash_proc(proc);

    // 设置新进程在进程链表中的前驱和后继
    set_links(proc);

    // 恢复中断
    local_intr_restore(intr_flag);

    // 唤醒新进程，使其开始运行
    wakeup_proc(proc);

    // 返回新进程的PID作为成功的标志
    ret = proc->pid;

fork_out:
    // 从fork操作中返回
    return ret;

bad_fork_cleanup_kstack:
    // 如果内核栈设置失败，释放内核栈
    put_kstack(proc);
bad_fork_cleanup_proc:
    // 如果内存复制失败，释放进程结构体所占用的内存
    kfree(proc);
    // 跳转到fork_out返回错误码
    goto fork_out;
}
```
do_fork 函数通过系统调用被触发，用于创建一个新的进程，该进程是当前进程的副本。新进程将被初始化并唤醒，以便执行。

1. 验证系统中当前的进程数量是否达到了最大限制 `MAX_PROCESS`。如果达到限制，则无法创建新的进程。
2. 为新进程分配一个进程控制块（`proc_struct`）。如果分配失败，则返回内存不足错误。
3. 为新进程分配内核栈空间。内核栈用于保存进程执行内核模式代码时的上下文信息。
4. 根据 `clone_flags` 参数决定是为新进程分配新的虚拟内存还是与父进程共享虚拟内存。
5. 获取父进程的上下文和中断帧，并设置新进程的上下文和中断帧，确保新进程能够从正确的位置开始执行。
6. 将新进程插入到进程管理的哈希表和进程链表中，使其成为系统中可管理的进程之一。
7. 唤醒新进程，使其可以从内核态切换到用户态，开始执行用户程序。
8. 返回新进程的ID（PID），作为创建进程操作成功的标识。

2. do_execve()函数

```c
int do_execve(const char *name, size_t len, unsigned char *binary, size_t size) {
    // 获取当前进程的内存管理结构体
    struct mm_struct *mm = current->mm;

    // 检查传入的程序名称是否是用户空间的有效内存
    if (!user_mem_check(mm, (uintptr_t)name, len, 0)) {
        return -E_INVAL; // 如果不是有效内存，返回错误码E_INVAL
    }

    // 如果程序名称长度超过进程名称的最大长度，则截断名称
    if (len > PROC_NAME_LEN) {
        len = PROC_NAME_LEN;
    }

    // 创建一个本地字符数组来存储程序名称，并将其初始化为0
    char local_name[PROC_NAME_LEN + 1];
    memset(local_name, 0, sizeof(local_name));
    // 将用户空间的程序名称复制到本地数组
    memcpy(local_name, name, len);

    // 如果当前进程有关联的内存管理结构体
    if (mm != NULL) {
        cputs("mm != NULL"); // 打印调试信息
        lcr3(boot_cr3); // 切换到内核页表

        // 减少mm的引用计数，如果为0则释放所有资源
        if (mm_count_dec(mm) == 0) {
            exit_mmap(mm); // 释放进程所有内存
            put_pgdir(mm); // 释放页目录
            mm_destroy(mm); // 销毁内存管理结构体
        }
        current->mm = NULL; // 将当前进程的mm指针设置为NULL
    }

    int ret; // 定义返回值变量
    // 加载新的程序二进制代码到内存中
    if ((ret = load_icode(binary, size)) != 0) {
        goto execve_exit; // 如果加载失败，跳转到错误处理
    }

    // 设置当前进程的名称为新的程序名称
    set_proc_name(current, local_name);
    return 0; // 加载成功，返回0

execve_exit: // 错误处理标签
    do_exit(ret); // 执行退出操作
    panic("already exit: %e.\n", ret); // 打印错误信息并终止系统
}
```
do_execve 函数首先验证输入参数的有效性，然后释放当前进程的内存资源，加载新的程序二进制代码，并设置新的进程名称。如果任何步骤失败，它将终止当前进程

3. do_wait()函数

```c
int do_wait(int pid, int *code_store) {
    // 获取当前进程的内存管理结构体
    struct mm_struct *mm = current->mm;
    
    // 如果用户提供了存储退出代码的地址，检查其有效性
    if (code_store != NULL) {
        if (!user_mem_check(mm, (uintptr_t)code_store, sizeof(int), 1)) {
            return -E_INVAL; // 如果地址无效，返回错误码E_INVAL
        }
    }

    struct proc_struct *proc;
    bool intr_flag, haskid;
repeat:
    // 初始化标志，用于标记是否有符合条件的子进程
    haskid = 0;
    // 如果指定了pid，查找特定的子进程
    if (pid != 0) {
        proc = find_proc(pid);
        if (proc != NULL && proc->parent == current) {
            haskid = 1; // 找到了符合条件的子进程
            if (proc->state == PROC_ZOMBIE) {
                goto found; // 如果子进程已经是僵尸进程，跳转到处理逻辑
            }
        }
    }
    // 如果没有指定pid，查找当前进程的所有子进程
    else {
        proc = current->cptr;
        for (; proc != NULL; proc = proc->optr) {
            haskid = 1;
            if (proc->state == PROC_ZOMBIE) {
                goto found;
            }
        }
    }
    // 如果有子进程，但都不是僵尸进程，使当前进程睡眠，等待子进程退出
    if (haskid) {
        current->state = PROC_SLEEPING;
        current->wait_state = WT_CHILD;
        schedule(); // 调度其他进程运行
        if (current->flags & PF_EXITING) {
            do_exit(-E_KILLED); // 如果当前进程被要求退出，执行退出操作
        }
        goto repeat; // 重新检查子进程状态
    }
    return -E_BAD_PROC; // 如果没有找到符合条件的子进程，返回错误码

found:
    // 如果找到的子进程是idleproc或initproc，打印错误信息并终止系统
    if (proc == idleproc || proc == initproc) {
        panic("wait idleproc or initproc.\n");
    }
    // 如果用户提供了存储退出代码的地址，将子进程的退出代码复制到用户空间
    if (code_store != NULL) {
        *code_store = proc->exit_code;
    }
    local_intr_save(intr_flag); // 禁用中断，保护临界区
    {
        unhash_proc(proc); // 从哈希表中移除子进程
        remove_links(proc); // 从链表中移除子进程
    }
    local_intr_restore(intr_flag); // 恢复中断
    put_kstack(proc); // 释放子进程的内核栈
    kfree(proc); // 释放子进程的内存
    return 0; // 返回成功
}
```

1. do_wait()函数用于等待一个子进程结束。如果`pid`参数不为0，它等待特定的子进程；如果`pid`为0，它等待任何一个子进程结束。
2. 函数首先检查如果用户提供了存储退出代码的地址，该地址是否有效。
3. 然后，根据`pid`参数的值，查找特定的子进程或遍历所有子进程。
4. 如果找到了已经变成僵尸进程的子进程，函数会处理子进程的退出，包括从哈希表和链表中移除子进程，复制子进程的退出代码到用户空间（如果需要），并释放子进程占用的资源。
5. 如果没有找到已经结束的子进程，当前进程会被置为睡眠状态，直到有子进程结束或当前进程被杀死。
6. 函数返回0表示成功，返回错误码表示失败。

4. do_exit()函数

```c
int do_exit(int error_code) {
    // 检查是否是特殊进程 idleproc 或 initproc，这两个进程不能退出
    if (current == idleproc) {
        panic("idleproc exit.\n");
    }
    if (current == initproc) {
        panic("initproc exit.\n");
    }

    // 获取当前进程的内存管理结构体
    struct mm_struct *mm = current->mm;
    // 如果当前进程有内存管理结构体，进行清理
    if (mm != NULL) {
        lcr3(boot_cr3); // 切换到内核页表
        // 减少内存管理结构体的引用计数，如果为0则进行内存清理
        if (mm_count_dec(mm) == 0) {
            exit_mmap(mm); // 退出内存映射
            put_pgdir(mm); // 释放页目录
            mm_destroy(mm); // 销毁内存管理结构体
        }
        current->mm = NULL; // 将当前进程的mm指针设置为NULL
    }

    // 设置当前进程状态为僵尸状态
    current->state = PROC_ZOMBIE;
    // 设置当前进程的退出代码
    current->exit_code = error_code;

    // 禁用中断，保护临界区
    bool intr_flag;
    struct proc_struct *proc;
    local_intr_save(intr_flag);

    // 唤醒等待当前进程的父进程
    proc = current->parent;
    if (proc->wait_state == WT_CHILD) {
        wakeup_proc(proc); // 唤醒父进程
    }

    // 将当前进程的所有子进程重新分配给 initproc
    while (current->cptr != NULL) {
        proc = current->cptr;
        current->cptr = proc->optr;

        proc->yptr = NULL;
        if ((proc->optr = initproc->cptr) != NULL) {
            initproc->cptr->yptr = proc;
        }
        proc->parent = initproc;
        initproc->cptr = proc;
        // 如果子进程已经是僵尸状态，尝试唤醒 initproc
        if (proc->state == PROC_ZOMBIE) {
            if (initproc->wait_state == WT_CHILD) {
                wakeup_proc(initproc);
            }
        }
    }

    // 恢复中断
    local_intr_restore(intr_flag);

    // 调度其他进程运行
    schedule();

    // 由于当前进程已经变为僵尸进程，不应该继续执行，这里 panic 表示错误
    panic("do_exit will not return!! %d.\n", current->pid);
}
```
1. do_exit 函数是操作系统内核中处理进程退出的关键函数。它负责清理进程资源，并更新进程状态。
2. 函数首先检查当前进程是否是特殊进程 idleproc 或 initproc，这两个进程是系统运行的关键，不能退出。
3. 然后，函数获取当前进程的内存管理结构体，并减少其引用计数。如果引用计数为0，说明没有其他进程使用这块内存，因此进行内存清理。
4. 接着，函数设置当前进程的状态为 PROC_ZOMBIE，并记录退出代码。
5. 函数在临界区内唤醒等待当前进程的父进程，并重新分配当前进程的所有子进程给 initproc。
6. 最后，函数调度其他进程运行，并由于当前进程已经变为僵尸进程，不应该继续执行，因此使用 panic 表示错误。

```c
    }

    int ret = 0;

    // 创建新的内存管理结构
    if ((mm = create_new_mm()) == NULL) {
        goto bad_mm;
    }

    // 设置新的页目录
    if (setup_new_pgdir(mm) != 0) {
        goto bad_pgdir_cleanup_mm;
    }

    // 锁定原进程的内存管理结构
    lock_old_mm(oldmm);

    // 复制内存映射
    ret = copy_mmap(mm, oldmm);

    // 解锁原进程的内存管理结构
    unlock_old_mm(oldmm);

    // 如果内存映射复制失败，进行清理
    if (ret != 0) {
        goto bad_dup_cleanup_mmap;
    }

good_mm:
    // 增加内存管理结构的引用计数
    increment_mm_ref_count(mm);

    // 设置进程的内存管理结构和 CR3 寄存器
    set_proc_mm_and_cr3(proc, mm);

    return 0;  // 返回成功

bad_dup_cleanup_mmap:
    // 清理内存映射
    cleanup_mmap(mm);

    // 清理页目录
    cleanup_pgdir(mm);

bad_pgdir_cleanup_mm:
    // 销毁内存管理结构
    destroy_mm(mm);

bad_mm:
    return ret;  // 返回错误码
}

int
cow_copy_mmap(struct mm_struct *to, struct mm_struct *from) {
    assert(to != NULL && from != NULL);
    list_entry_t *list = &(from->mmap_list), *le = list;
    while ((le = list_prev(le)) != list) {
        struct vma_struct *vma, *nvma;
        vma = le2vma(le, list_link);
        nvma = vma_create(vma->vm_start, vma->vm_end, vma->vm_flags);
        if (nvma == NULL) {
            return -E_NO_MEM;
        }
        insert_vma_struct(to, nvma);
        if (cow_copy_range(to->pgdir, from->pgdir, vma->vm_start, vma->vm_end) != 0) {
            return -E_NO_MEM;
        }
    }
    return 0;
}

// 检查地址是否有效，并获取页表项
pte_t *get_valid_pte(pde_t *pgdir, uintptr_t addr) {
    pte_t *ptep = get_pte(pgdir, addr, 0);  // 获取页表项
    if (ptep == NULL) {
        return NULL;  // 如果页表项为空，返回NULL
    }
    return ptep;
}

// 检查页面是否有效
int check_and_prepare_page(pte_t *ptep, uintptr_t *start, uint32_t *perm) {
    if (*ptep & PTE_V) {  // 如果该页是有效的
        *ptep &= ~PTE_W;  // 只读权限，清除写权限
        *perm = (*ptep & PTE_USER & ~PTE_W);  // 计算新的权限
        return 0;  // 成功
    }
    return -1;  // 如果页表项无效，返回错误
}

// 进行页面复制操作
int insert_page(pde_t *to, pte_t *ptep, uintptr_t start, uint32_t perm) {
    struct Page *page = pte2page(*ptep);  // 获取页面结构
    assert(page != NULL);  // 确保页面结构有效
    int ret = page_insert(to, page, start, perm);  // 将页面插入目标页表
    assert(ret == 0);  // 确保页面插入成功
    return ret;
}

// 复制内存范围
int cow_copy_range(pde_t *to, pde_t *from, uintptr_t start, uintptr_t end) {
    assert(start % PGSIZE == 0 && end % PGSIZE == 0);  // 确保起始地址和结束地址是页面大小的倍数
    assert(USER_ACCESS(start, end));  // 确保访问的地址范围是合法的用户空间范围

    while (start < end) {  // 遍历整个内存范围
        pte_t *ptep = get_valid_pte(from, start);  // 获取源进程的页表项
        if (ptep == NULL) {  // 如果没有对应的页表项
            start = ROUNDDOWN(start + PTSIZE, PTSIZE);  // 跳到下一页
            continue;
        }

        uint32_t perm;
        if (check_and_prepare_page(ptep, &start, &perm) == 0) {  // 如果页表项有效并且准备好权限
            insert_page(to, ptep, start, perm);  // 将页面插入目标页表
        }
        start += PGSIZE;  // 处理下一个页面
    }
    return 0;  // 返回成功
}

    uintptr_t* dst = page2kva(npage);  // 获取新页面的内核虚拟地址

    print_page_fault(addr);  // 打印页故障的地址
    int ret = 0;
    // 获取页表项
    pte_t *ptep = get_pte_for_fault(mm, addr);
    // 设置新的权限，允许写操作
    uint32_t perm = set_write_permission(ptep);
    // 获取原页面结构
    struct Page *page = pte2page(*ptep);
    // 分配新页面
    struct Page *npage = allocate_new_page();
    // 确保原页面有效
    assert(page != NULL);  
    // 复制页面内容
    copy_page_content(page, npage);
    // 获取页面对齐的起始地址
    uintptr_t start = ROUNDDOWN(addr, PGSIZE);
    // 清空页表项
    *ptep = 0;
    // 将新页面插入页表
    ret = insert_new_page_to_pgdir(mm, npage, start, perm);
    // 重新获取页表项
    ptep = get_pte(mm->pgdir, addr, 0);

    return ret;  // 返回结果
}
```

##### cow设计思路

setup_pgdir和put_pgdir与proc.c中一致

1. **初始化目标进程页目录 (setup_pgdir)**

```c
static int setup_pgdir(struct mm_struct *mm) {
    struct Page *page;
    // 分配一页内存作为页目录
    if ((page = alloc_page()) == NULL) {
        return -E_NO_MEM;  // 如果分配失败，返回错误码
    }
    
    pde_t *pgdir = page2kva(page);  // 获取分配页的内核虚拟地址
    memcpy(pgdir, boot_pgdir, PGSIZE);  // 复制内核的页目录到新页目录

    mm->pgdir = pgdir;  // 将新页目录赋给 mm 结构
    return 0;
}
```

- 该函数负责为进程（通过 `mm_struct` 表示）分配页目录。
- `alloc_page()` 用于分配一页物理内存，作为该进程的页目录。
- `page2kva(page)` 将物理页转化为内核虚拟地址。
- 将系统的默认页目录 `boot_pgdir` 复制到新页目录中，确保进程有一个合适的初始页目录。
- 最后将新页目录的虚拟地址保存到进程的 `mm->pgdir` 字段中。

2. **释放页目录内存 (put_pgdir)**

```c
static void put_pgdir(struct mm_struct *mm) {
    free_page(kva2page(mm->pgdir));  // 释放页目录对应的物理页
}
```

- 该函数释放进程页目录所占用的物理内存。
- `kva2page(mm->pgdir)` 将虚拟地址转回物理页对象，然后使用 `free_page()` 释放这块物理内存。

3. **COW 复制内存管理 (cow_copy_mm)**

 **Copy-on-Write (COW)** 内存管理的复制操作，具体是复制一个进程的内存管理结构（`mm_struct`）。该操作主要涉及内存映射的复制、页目录的设置、新的内存管理结构的创建等。

（1）**检查是否是内核线程 (`check_if_kernel_thread`)**

```c
int check_if_kernel_thread(struct mm_struct *oldmm) {
    if (oldmm == NULL) {
        return 0;  // 如果是内核线程，直接返回
    }
    return 1;
}
```

- **功能**：检查当前进程是否是内核线程。
- 思路
  - 如果 `oldmm == NULL`，则说明当前进程没有用户空间的内存管理结构，通常意味着它是内核线程，因为内核线程不需要用户空间内存管理（即没有用户空间的页表）。因此直接返回 `0`，表示是内核线程。
  - 如果 `oldmm != NULL`，说明进程有用户空间的内存管理结构，返回 `1` 表示不是内核线程。

（2）**创建新的内存管理结构 (`create_new_mm`)**

```c
struct mm_struct *create_new_mm() {
    struct mm_struct *mm = mm_create();
    return mm;
}
```

- **功能**：创建一个新的内存管理结构 `mm_struct`。
- 思路
  - 调用 `mm_create()` 函数分配并初始化一个新的内存管理结构 `mm`，该结构将用于新进程的内存管理。
  - 返回新创建的 `mm` 结构。

（3）**设置新的页目录 (`setup_new_pgdir`)**

```c
int setup_new_pgdir(struct mm_struct *mm) {
    return setup_pgdir(mm);
}
```

- **功能**：设置新进程的页目录。
- 思路
  - 调用 `setup_pgdir()` 函数为新创建的 `mm_struct` 设置页目录。
  - 该函数通常会创建一个新的页目录，初始化它，以供进程管理虚拟地址空间。

（4） **锁定内存管理结构 (`lock_old_mm`)**

```c
void lock_old_mm(struct mm_struct *oldmm) {
    lock_mm(oldmm);
}
```

- **功能**：锁定原进程的内存管理结构，防止并发修改。
- 思路
  - 调用 `lock_mm()` 锁定原进程的内存管理结构 `oldmm`，防止在复制过程中其他线程或进程修改原进程的内存管理结构。

（5）**解锁内存管理结构 (`unlock_old_mm`)**

```c
void unlock_old_mm(struct mm_struct *oldmm) {
    unlock_mm(oldmm);
}
```

- **功能**：解锁原进程的内存管理结构。
- 思路
  - 调用 `unlock_mm()` 解锁原进程的内存管理结构，使其他进程或线程可以访问 `oldmm`。

（6） **复制内存映射 (`copy_mmap`)**

```c
int copy_mmap(struct mm_struct *mm, struct mm_struct *oldmm) {
    return cow_copy_mmap(mm, oldmm);
}
```

- **功能**：复制原进程的内存映射。
- 思路
  - 调用 `cow_copy_mmap()` 函数进行内存映射的复制操作，将 `oldmm` 中的内存映射复制到新的内存管理结构 `mm` 中。
  - 如果复制失败，则返回非零值，表示操作失败。

（7）**增加内存管理结构的引用计数 (`increment_mm_ref_count`)**

```c
void increment_mm_ref_count(struct mm_struct *mm) {
    mm_count_inc(mm);
}
```

- **功能**：增加内存管理结构的引用计数。
- 思路
  - 调用 `mm_count_inc()` 增加 `mm` 的引用计数，表示当前有一个新的进程正在使用该内存管理结构。

（8） **设置进程的内存管理结构和 CR3 寄存器 (`set_proc_mm_and_cr3`)**

```c
void set_proc_mm_and_cr3(struct proc_struct *proc, struct mm_struct *mm) {
    proc->mm = mm;
    proc->cr3 = PADDR(mm->pgdir);
}
```

- **功能**：将新的内存管理结构和页目录设置到进程中。
- 思路
  - 将 `mm` 设置为 `proc`（目标进程）的内存管理结构 `mm`。
  - 将新的页目录的物理地址（通过 `PADDR(mm->pgdir)` 获取）设置到进程的 `cr3` 寄存器中。`cr3` 寄存器是 x86 架构中保存页目录物理地址的寄存器。

（9）**清理内存映射 (`cleanup_mmap`)**

```c
void cleanup_mmap(struct mm_struct *mm) {
    exit_mmap(mm);
}
```

- **功能**：清理内存映射。
- 思路
  - 调用 `exit_mmap()` 清理 `mm` 中的内存映射。这个操作通常会释放内存映射中所有的资源，例如解除映射的页面等。

（10）**清理页目录 (`cleanup_pgdir`)**

```c
void cleanup_pgdir(struct mm_struct *mm) {
    put_pgdir(mm);
}
```

- **功能**：清理页目录。
- 思路
  - 调用 `put_pgdir()` 释放 `mm` 中的页目录，释放页目录占用的内存。

（11）**销毁内存管理结构 (`destroy_mm`)**

```c
void destroy_mm(struct mm_struct *mm) {
    mm_destroy(mm);
}
```

- **功能**：销毁内存管理结构。
- 思路
  - 调用 `mm_destroy()` 销毁内存管理结构 `mm`，释放与该结构相关的所有资源。

(12)**主函数：复制内存管理结构 (`cow_copy_mm`)**

```c
int cow_copy_mm(struct proc_struct *proc) {
    struct mm_struct *mm, *oldmm = current->mm;

    // 检查是否是内核线程
    if (!check_if_kernel_thread(oldmm)) {
        return 0;
    }

    int ret = 0;

    // 创建新的内存管理结构
    if ((mm = create_new_mm()) == NULL) {
        goto bad_mm;
    }

    // 设置新的页目录
    if (setup_new_pgdir(mm) != 0) {
        goto bad_pgdir_cleanup_mm;
    }

    // 锁定原进程的内存管理结构
    lock_old_mm(oldmm);

    // 复制内存映射
    ret = copy_mmap(mm, oldmm);

    // 解锁原进程的内存管理结构
    unlock_old_mm(oldmm);

    // 如果内存映射复制失败，进行清理
    if (ret != 0) {
        goto bad_dup_cleanup_mmap;
    }

good_mm:
    // 增加内存管理结构的引用计数
    increment_mm_ref_count(mm);

    // 设置进程的内存管理结构和 CR3 寄存器
    set_proc_mm_and_cr3(proc, mm);

    return 0;  // 返回成功

bad_dup_cleanup_mmap:
    // 清理内存映射
    cleanup_mmap(mm);

    // 清理页目录
    cleanup_pgdir(mm);

bad_pgdir_cleanup_mm:
    // 销毁内存管理结构
    destroy_mm(mm);

bad_mm:
    return ret;  // 返回错误码
}
```

- **功能**：复制内存管理结构，创建新的内存管理结构并设置页目录等。
- 思路
  1. **检查内核线程**：首先检查当前进程是否是内核线程，如果是，则直接返回 `0`。
  2. **创建新的内存管理结构**：为新进程创建一个新的内存管理结构。
  3. **设置页目录**：为新进程设置新的页目录。
  4. **锁定并复制内存映射**：锁定原进程的内存管理结构，复制内存映射（通过 `cow_copy_mmap`）。
  5. **清理和回滚**：如果内存映射复制失败，则清理之前的操作（销毁页目录和内存管理结构）。
  6. **更新进程**：如果所有步骤成功，则增加内存管理结构的引用计数，更新进程的内存管理结构和 CR3 寄存器。
  7. **返回**：返回 `0` 表示成功，如果失败则返回相应的错误码。



4. **复制虚拟内存区域和页表 (cow_copy_mmap)**

```c
int cow_copy_mmap(struct mm_struct *to, struct mm_struct *from) {
    assert(to != NULL && from != NULL);
    list_entry_t *list = &(from->mmap_list), *le = list;
    
    while ((le = list_prev(le)) != list) {  // 遍历 from 的 VMA 链表
        struct vma_struct *vma, *nvma;
        vma = le2vma(le, list_link);  // 获取当前 VMA
        
        // 创建新的 VMA 并插入到目标 mm 的链表中
        nvma = vma_create(vma->vm_start, vma->vm_end, vma->vm_flags);
        if (nvma == NULL) {
            return -E_NO_MEM;  // 如果创建失败，返回错误码
        }
        insert_vma_struct(to, nvma);  // 插入 VMA

        // 复制虚拟内存区域的页表
        if (cow_copy_range(to->pgdir, from->pgdir, vma->vm_start, vma->vm_end) != 0) {
            return -E_NO_MEM;
        }
    }
    return 0;
}
```

- 该函数负责复制进程的虚拟内存区域（VMA）和页表。
- 遍历源进程 `from` 的 VMA 链表，对于每个 VMA 创建新的 VMA 并插入目标进程的 VMA 链表。
- 然后调用 `cow_copy_range()` 复制虚拟内存区域所对应的页表。
- 在复制过程中，如果有内存分配失败的情况，将返回 `-E_NO_MEM` 错误。

5. **复制页表范围 (cow_copy_range)**

可以分为几个步骤:

(1)**获取页表项 (`get_valid_pte`)**


- **功能**：**获取某个地址对应的页表项**。页表项是虚拟地址到物理地址的映射，包含了页面的状态和权限信息。
- 思路
  - 使用 `get_pte` 函数获取指定虚拟地址 `addr` 在页目录 `pgdir` 中的页表项。
  - 如果返回的 `ptep` 是 `NULL`，说明该地址没有有效的页表项，函数返回 `NULL`。
  - 否则，返回页表项 `ptep`，表示找到了该地址的页表项。

(2)**检查并准备页面权限 (`check_and_prepare_page`)**

```c

    }

```

- **功能**：检查一个页面是否有效，并为后续操作准备好页面权限。
- 思路
  - 如果页表项的有效位 (`PTE_V`) 被设置，表示该页面是有效的。然后：
    - 将 `PTE_W` 清除，表示该页面变为只读。
    - 从页表项中提取权限位 `PTE_USER` 和 `PTE_W`，得到该页面的最终权限，并存储在 `perm` 中。
  - 如果页表项无效，则返回错误（`-1`），表示无法复制该页面。

(3)**插入页面到目标页表 (`insert_page`)**

```c

    return ret;

```

- **功能**：将一个有效的页面插入目标进程的页表。
- 思路:
  - 使用 `pte2page` 将页表项转换为实际的物理页面 `struct Page`。
  - 通过 `page_insert` 将这个页面插入目标页表，并设置相应的权限。
  - `assert(ret == 0)` 确保插入操作成功，否则发生错误。

(4)**复制内存范围 (`cow_copy_range`)**

```c
int cow_copy_range(pde_t *to, pde_t *from, uintptr_t start, uintptr_t end) {
    assert(start % PGSIZE == 0 && end % PGSIZE == 0);  // 确保起始地址和结束地址是页面大小的倍数
    assert(USER_ACCESS(start, end));  // 确保访问的地址范围是合法的用户空间范围

    while (start < end) {  // 遍历整个内存范围
        pte_t *ptep = get_valid_pte(from, start);  // 获取源进程的页表项
        if (ptep == NULL) {  // 如果没有对应的页表项
            start = ROUNDDOWN(start + PTSIZE, PTSIZE);  // 跳到下一页
            continue;
        }

        uint32_t perm;
        if (check_and_prepare_page(ptep, &start, &perm) == 0) {  // 如果页表项有效并且准备好权限
            insert_page(to, ptep, start, perm);  // 将页面插入目标页表
        }
        start += PGSIZE;  // 处理下一个页面
    }
    return 0;  // 返回成功
}
```

- **功能**：该函数用于遍历给定的内存范围（从 `start` 到 `end`），复制每个页面并将其插入目标页表。
- 思路
  - 确保 `start` 和 `end` 是页面对齐的，并且地址范围属于合法的用户空间（通过 `USER_ACCESS` 检查）。
  - 遍历 `start`到``end` 的每一页（`start` 每次增加 `PGSIZE`）。
    - 对于每一页，首先通过 `get_valid_pte` 获取源进程的页表项。
    - 如果页表项无效（`NULL`），则跳到下一页。
    - 如果页表项有效，则调用 `check_and_prepare_page` 准备页面的权限，并调用 `insert_page` 将页面插入目标页表。
  - 最后，返回 `0` 表示成功完成内存范围的复制。

通过这种方式，只有在需要修改（写入）页面时才会进行页面复制，从而节省了内存并支持懒复制（lazy copy）策略，这是 COW 技术的核心理念。

6. **处理 COW 页错误 (cow_pgfault)**

核心逻辑是处理 **Copy-on-Write** (COW) 页故障。当进程尝试写入一个只读的 COW 页面时，会触发页故障。处理步骤包括：

1. 打印页故障地址。
2. 获取源页的页表项。
3. 为页面分配新的物理内存页面，并复制原页面的内容。
4. 更新页表项，将新页面插入页表，并修改权限为可写。
5. 清除旧页面的页表项，完成 COW 操作。

通过这种方式，COW 技术有效地延迟了页面的复制，避免了不必要的内存消耗，只有在写操作发生时才进行页面复制。

(1)**打印页故障的地址 (`print_page_fault`)**

```c
void print_page_fault(uintptr_t addr) {
    cprintf("COW page fault at 0x%x\n", addr);
}
```

- **功能**：该函数用于打印发生页故障时的虚拟地址。
- 思路
  - 使用 `cprintf` 打印出当前发生 COW 页故障的地址 `addr`，以便进行调试或日志记录。这个操作对分析 COW 页故障非常有帮助，特别是在调试阶段。

(2)**获取页表项 (`get_pte_for_fault`)**

```c
pte_t *get_pte_for_fault(struct mm_struct *mm, uintptr_t addr) {
    return get_pte(mm->pgdir, addr, 0);
}
```

- **功能**：该函数用于获取一个指定地址的页表项（`pte_t`），并返回其指针。
- 思路
  - 通过 `get_pte` 函数，获取 `mm`（进程的内存管理结构）中的页目录 `pgdir` 下，对应地址 `addr` 的页表项。
  - `get_pte` 函数用于从页目录中查找页表项。如果该地址没有对应的页表项，返回 `NULL`。

(3)**设置页面的写权限 (`set_write_permission`)**

```c
uint32_t set_write_permission(pte_t *ptep) {
    return (*ptep & PTE_USER) | PTE_W;
}
```

- **功能**：该函数用于设置页面的写权限。
- 思路
  - 函数接收一个指向页表项的指针 `ptep`。
  - 根据 COW 的需求，我们需要将页面权限设置为可写，即将 `PTE_W` 位设置为 1。
  - 同时，我们保留 `PTE_USER` 位，确保该页面仍然是用户空间可访问的。
  - 最后，返回修改后的权限值。

(4)**分配新页面 (`allocate_new_page`)**

```c
struct Page *allocate_new_page() {
    struct Page *npage = alloc_page();
    assert(npage != NULL);  // 确保新页面有效
    return npage;
}
```

- **功能**：该函数用于分配一个新的页面。
- 思路
  - 调用 `alloc_page()` 分配一个新的页面，并返回页面结构体 `npage`。
  - 使用 `assert(npage != NULL)` 确保新页面分配成功，如果 `alloc_page` 返回 `NULL`，则表示分配失败，程序会触发断言。

(5)**复制原页面内容到新页面 (`copy_page_content`)**

```c
void copy_page_content(struct Page *page, struct Page *npage) {
    uintptr_t* src = page2kva(page);  // 获取原页面的内核虚拟地址
    uintptr_t* dst = page2kva(npage);  // 获取新页面的内核虚拟地址
    memcpy(dst, src, PGSIZE);  // 将原页面内容复制到新页面
}
```

- **功能**：该函数用于将原页面的内容复制到新分配的页面。
- 思路
  - 使用 `page2kva` 函数将原页面和新页面转换为内核虚拟地址。
  - 使用 `memcpy` 将原页面的内容复制到新页面中，确保新页面具有原页面相同的内容。

(6)**插入新页面到页表 (`insert_new_page_to_pgdir`)**

```c
int insert_new_page_to_pgdir(struct mm_struct *mm, struct Page *npage, uintptr_t start, uint32_t perm) {
    return page_insert(mm->pgdir, npage, start, perm);
}
```

- **功能**：该函数用于将新分配的页面插入到进程的页表中。
- 思路
  - 使用 `page_insert` 函数将新页面 `npage` 插入进程的页表（通过 `mm->pgdir` 指定）。
  - 在插入时，需要指定起始地址 `start` 和权限 `perm`，后者通常是可写的。

(7)**处理 COW 页故障 (`cow_pgfault`)**

```c
int cow_pgfault(struct mm_struct *mm, uint_t error_code, uintptr_t addr) {
    print_page_fault(addr);  // 打印页故障的地址
    int ret = 0;
    // 获取页表项
    pte_t *ptep = get_pte_for_fault(mm, addr);
    // 设置新的权限，允许写操作
    uint32_t perm = set_write_permission(ptep);
    // 获取原页面结构
    struct Page *page = pte2page(*ptep);
    // 分配新页面
    struct Page *npage = allocate_new_page();
    // 确保原页面有效
    assert(page != NULL);  
    // 复制页面内容
    copy_page_content(page, npage);
    // 获取页面对齐的起始地址
    uintptr_t start = ROUNDDOWN(addr, PGSIZE);
    // 清空页表项
    *ptep = 0;
    // 将新页面插入页表
    ret = insert_new_page_to_pgdir(mm, npage, start, perm);
    // 重新获取页表项
    ptep = get_pte(mm->pgdir, addr, 0);
    return ret;  // 返回结果
}
```

- **功能**：该函数处理发生 COW 页故障的情况，并执行必要的操作来复制页面并更新页表。
- 思路
  - 打印发生页故障的地址，便于调试。
  - 使用 `get_pte_for_fault` 获取发生故障的地址的页表项。
  - 设置新页面的写权限，允许修改页面内容。
  - 从页表项中获取原页面，并确保原页面有效。
  - 为原页面分配一个新页面。
  - 将原页面的内容复制到新页面。
  - 获取页面对齐的起始地址，以确保插入页表时地址对齐。
  - 清空原页表项，表示该页面已经不再共享（从 COW 到写时复制状态）。
  - 将新页面插入页表。
  - 最后，重新获取页表项（此操作可能是冗余的，可用于后续操作或验证）。

#### 2. 说明该用户程序是何时被预先加载到内存中的？与我们常用操作系统的加载有何区别，原因是什么？

该用户程序在操作系统加载时一起加载到内存里。我们平时使用的程序在操作系统启动时还位于磁盘中，只有当我们需要运行该程序时才会被加载到内存里。
原因是在Makefile里执行了ld命令，把执行程序的代码连接在了内核代码的末尾。
首先用户程序的编译是通过 add_files_cc 函数和 create_target_cc 函数来完成的。这些函数在 Makefile 中被调用来添加用户程序的源文件，并创建编译目标

```
$(call add_files_cc,$(call listf_cc,$(ULIBDIR)),ulibs,$(UCFLAGS))
$(call add_files_cc,$(call listf_cc,$(USRCDIR)),uprog,$(UCFLAGS))
```
接下来用户程序被链接成单独的二进制文件，这是通过 define uprog_ld 宏来完成的。每个用户程序都会被链接成以 __user_ 为前缀的二进制文件。
```
define uprog_ld
__user_bin__ := $$(call ubinfile,$(1))
USER_BINS += $$(__user_bin__)
$$(__user_bin__): tools/user.ld
$$(__user_bin__): $$(UOBJS)
$$(__user_bin__): $(1) | $$$$(dir $$$$@)
    $(V)$(LD) $(LDFLAGS) -T tools/user.ld -o $$@ $$(UOBJS) $(1)
    ...
endef
```
接着在创建内核映像 kernel 的过程中，用户程序的二进制文件被整合到内核映像中。这是通过在链接命令中包含 --format=binary $(USER_BINS) 来实现的
```
$(kernel): $(KOBJS) $(USER_BINS)
    ...
    $(V)$(LD) $(LDFLAGS) -T tools/kernel.ld -o $@ $(KOBJS) --format=binary $(USER_BINS) --format=default
...
```
最后UCOREIMG 目标将内核映像转换为一个二进制镜像文件 ucore.img，这个文件包含了内核代码和预先加载的用户程序
```
$(UCOREIMG): $(kernel)
$(OBJCOPY) $(kernel) --strip-all -O binary $@
```
